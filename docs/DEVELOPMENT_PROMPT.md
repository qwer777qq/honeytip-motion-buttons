# 워드프레스 `/버튼` 선택형 움직이는 버튼 개발 프롬프트

## 2026-10-23 확장 지시: 8종으로 완성

아래의 기존 4종 요구사항을 그대로 지키면서 [GitHub 움직이는 버튼 데모](https://qwer777qq.github.io/honeytip-motion-buttons/)와 [코드](https://github.com/qwer777qq/honeytip-motion-buttons)를 확인해 **추가 색상 4종**을 구현한다. `wordpress/honeytip-motion-buttons/`의 독립 플러그인에는 `버튼 · 코랄 점프`, `버튼 · 앰버 빛 스윕`, `버튼 · 민트 화살표`, `버튼 · 로즈 채움` 패턴이 들어 있다. 설치 전에는 새 4종이 사이트에 등록되어 있다고 말하지 말고, 기존 4종을 중복 등록하지 않는다.

내 버튼의 실제 사용 예시인 [비짓재팬 글](https://honeytipmagazine.com/%eb%b9%84%ec%a7%93%ec%9e%ac%ed%8c%ac-%eb%93%b1%eb%a1%9d%eb%b0%a9%eb%b2%95-%ec%9d%bc%eb%b3%b8%ec%97%ac%ed%96%89-%ec%a4%80%eb%b9%84%eb%ac%bc-%ec%82%ac%ec%9d%b4%ed%8a%b8-%ec%9b%b9-%ec%95%88%eb%82%b4/)과 [디지털온누리상품권 환불 글](https://honeytipmagazine.com/%eb%94%94%ec%a7%80%ed%84%b8%ec%98%a8%eb%88%84%eb%a6%ac%ec%83%81%ed%92%88%ea%b6%8c-%ed%99%98%eb%b6%88-%eb%b0%a9%eb%b2%95-2026/)을 먼저 확인한다. 환불 글의 `honey-cta`는 확인 당시 데스크톱에서 480×64px, 남색 그라데이션, 14px 모서리와 선명한 그림자를 가졌다. 기존 글의 버튼과 목적지 URL을 유지한다.

전문 사이트는 [Apple의 분명한 행동 문구](https://www.apple.com/kr/iphone/), [Stripe의 주·보조 CTA 구분](https://stripe.com/), [GitHub Primer의 Primary 버튼 절제](https://primer.style/product/components/button/), [GOV.UK의 행동을 설명하는 문구](https://design-system.service.gov.uk/components/button/)를 참고한다. 구체적 비교는 저장소 `docs/BENCHMARK.md`를 본다. 다른 사이트의 CSS와 이미지는 복사하지 않는다.

먼저 현재 사이트의 기존 패턴, CSS, 글 링크를 읽기 전용으로 확인하고 백업한 뒤 새 4종을 추가한다. `/버튼` 검색에서 8종이 구별되는지, 글마다 문구와 URL이 독립적으로 편집되는지, 390px 모바일·Tab 키·모션 축소 설정에서 정상인지 확인한다. 기존 비짓재팬 및 환불 글의 버튼과 링크가 그대로인지 전후를 비교한다. 테스트 초안은 공개하지 않는다.

## 목표

글을 쓰는 사람이 빈 문단에서 `/버튼`을 입력하면 움직이는 CTA를 쉽게 찾고, 아래 네 가지 스타일 중 하나를 골라 글에 넣을 수 있게 한다. 삽입 후 버튼 문구와 목적지 URL을 블록 편집 화면에서 직접 바꿀 수 있어야 한다. HTML 코드 편집을 요구하지 않는다. 버튼은 글 본문 중앙에 정렬한다.

## 선택지

1. **입체 점프**: 마우스 진입 시 짧게 위로 솟았다가 안정된 위치로 내려오고, 화살표가 대각선으로 이동한다. 기존 버튼의 남색 그라데이션과 노란 화살표를 계승한다.
2. **빛 스윕**: 마우스 진입 시 빛줄기가 버튼을 한 번 가로질러 간다. 움직임은 짧고 눈부시지 않게 한다.
3. **화살표 슬라이드**: 버튼 본체는 가볍게 떠오르고, 우측 원형 화살표가 옆으로 미끄러지듯 움직인다.
4. **테두리 채움**: 기본 상태는 남색 윤곽선, 호버 시 남색 배경이 채워진다. 텍스트 대비가 전환 중에도 충분해야 한다.

각 선택지 이름 앞에 `버튼 ·`을 붙여 검색하기 쉽게 한다. 단순한 모양 차이에 그치지 않고 실제 글 화면에서 움직임이 구분되어야 한다. 지나친 반복 애니메이션은 피하고 마우스 진입이나 포커스 때 한 번 반응하게 한다.

## 현재 등록 위치

워드프레스 관리자 `모양 → 디자인 → 패턴`의 `버튼` 카테고리에서 네 패턴을 관리한다. 패턴 편집 주소와 스타일 클래스는 아래와 같다. 공통 스타일과 변형 스타일은 `모양 → 사용자 정의 → 추가 CSS`에 발행되어 있다.

| 패턴 | 패턴 ID | 스타일 클래스 |
| --- | ---: | --- |
| 버튼 · 입체 점프 | 14768 | `honey-cta` |
| 버튼 · 빛 스윕 | 14873 | `honey-cta honey-cta--sweep` |
| 버튼 · 화살표 슬라이드 | 14884 | `honey-cta honey-cta--arrow` |
| 버튼 · 테두리 채움 | 14887 | `honey-cta honey-cta--fill` |

초보자 사용 흐름: 새 글의 빈 문단에서 `/버튼` 입력 → 원하는 `버튼 · …` 패턴 선택 → 버튼 문구 수정 → 링크 도구에서 URL 입력. 워드프레스 기본 `버튼` 블록도 같은 검색 결과에 보이므로 패턴 이름까지 확인해 선택한다.

## 구현 요구사항

- 현재 사이트에는 비동기화 패턴 네 개와 공통 CSS가 등록되어 있다. `/버튼` 검색 결과에 네 패턴이 나타나고, 삽입한 글에서 문구와 URL을 별도로 바꿀 수 있음도 확인했다. 먼저 이 설정을 유지하며 다듬는다. 향후 편집기 업데이트로 `/버튼` 검색이 동작하지 않을 때에만 사이트 전용 Gutenberg 블록이나 블록 변형을 검토한다.
- 기존 `버튼 · 입체 점프` 패턴과 `.honey-cta` 스타일을 조사해 중복 규칙과 충돌을 피한다. 이미 발행된 글의 버튼과 링크를 훼손하지 않는다. 신규 버튼 스타일은 고유 클래스 이름으로 범위를 좁힌다.
- 각 삽입 인스턴스의 문구와 URL은 독립적으로 편집되게 한다. URL 미입력 시 오작동하는 `#` 링크를 저장하지 말고, 편집 화면에서 URL 설정을 분명히 안내한다. 새 창 열기 선택 시 `rel="noopener noreferrer"`를 적용한다.
- 기본 배치는 가운데 정렬, 최대 폭 480px, 좁은 화면에서는 부모 너비 안에 들어가도록 `width:min(100%, 480px)`와 `box-sizing:border-box`를 사용한다. 한국어 긴 문구가 잘리지 않아야 한다.
- 키보드 Tab 포커스에서 버튼이 명확히 보이고 Enter로 링크가 열린다. `:focus-visible`, 충분한 색 대비, 최소 44px 터치 높이를 제공한다.
- 터치 화면에서는 호버에 의존하지 않는다. 눌림 상태만 자연스럽게 반응한다. `prefers-reduced-motion: reduce`에서는 애니메이션을 제거한다.
- 애니메이션은 `transform`과 `opacity` 중심으로 구현하고 레이아웃을 흔드는 속성 변경을 피한다. 모바일에서 가로 스크롤이 생기지 않아야 한다.
- 워드프레스·테마 업데이트에 견디도록 코어 파일을 직접 수정하지 않는다. 기존 CSS는 백업하고, 가능하면 작은 사이트 전용 플러그인이나 자식 테마를 사용한다.

## 검증과 인계

1. 새 글 초안에서 `/버튼`으로 네 선택지가 검색되는지 확인한다. 검색이 패턴을 지원하지 않으면 완성될 때까지 구현 방식을 조정한다.
2. 각 선택지를 한 번씩 넣어 문구·URL을 바꾸고, 편집기 미리보기와 실제 프런트 화면의 중앙 정렬·링크 이동을 확인한다.
3. 데스크톱 호버, 390px 전후 모바일, 키보드 포커스, 모션 축소 설정을 확인한다. 기존 비짓재팬 글의 세 버튼도 정상 작동해야 한다.
4. 결과물과 함께 초보자용 사용법을 세 줄로 남긴다: `새 글 → 빈 문단에 /버튼 → 스타일 선택 → 문구와 링크 입력`.
5. 작업 전후 화면과 적용 파일·설정 위치를 기록한다. 테스트용 초안은 공개하지 않는다.
